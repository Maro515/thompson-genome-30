# 執筆仕様 — パート修了「エピソードトーク」

各 Part の最終日の末尾に置く、**読み物としてのエピソード**を1本書く。成果物は
`build/episodes/epN.json`（N = パート番号）1ファイル。

ねらいは娯楽ではなく**記憶の定着**。そのパートで学んだ概念が、実在の出来事の中で
「どう使われたか／どう発見されたか」を見せることで、知識に手触りと順番を与える。

## 0. 最初にやること

1. `build/days/day01.json` を読み、文体・記法・キャラクターの喋り方を掴む。
2. `build/SPEC.md` の §2（登場人物）§3（インライン記法）§4のブロック型を読む。**同じブロック型を使う**。
3. `build/plan.json` で、担当パートに含まれる Day の `title` と `focus` を確認する。
   **エピソードは、そのパートで実際に学んだ語彙だけで書く**（先の章の用語は使わない）。

## 1. 精度に関する絶対ルール（本編より厳しい）

これは**実在の人物・出来事**を扱う。教科書の外の話なので、裏取りの責任はこちらにある。

- **年号・人名・所属・数値を創作しない。** 確信が持てないものは書かない、または
  「およそ」「〜年代」「諸説ある」と明示的に幅を持たせる。
- **セリフを捏造しない。** 実際の発言として引用してよいのは、広く知られた短い一句のみ。
  その場合も「〜と書いた／述べたと伝えられる」と出典の性格を添える。長い引用は禁止。
- 論文・出来事は**発表年と媒体**が言えるものだけを断定形で書く。
- **故人と遺族の尊厳を守る。** 検体・細胞・家系情報が本人の同意なく使われた事例では、
  被害を娯楽として消費しない。何が起きたか、当時の規範は何だったか、いま何が変わったかを書く。
- 特定の民族・集団・家系を「疾患の集団」として名指ししない。創始者効果を語るときは、
  それが**集団の性質ではなく歴史の産物**であることを明示する。
- 疑わしい通説（後年に否定された逸話、単純化されすぎた英雄譚）は、**通説として紹介したうえで
  現在の理解を書く**。人物を一方的な悪役／被害者にしない。
- WebSearch / WebFetch が使えるなら、**年号・肩書き・論文誌名は必ず裏を取る**。
  取れなかったものは断定を外す。

## 2. 構成（`blocks` は本編と同じ型）

長さは本編1日の **3〜4割**（talk 20〜30ブロック、目安7〜10分）。

1. **つかみ** — 場面から入る。日付・場所・誰が何を見ていたか。
2. **本筋** — 出来事を時系列で。ここで**そのパートで学んだ概念**を必ず名指しして接続する
   （例:「これが Day 18 でやった連鎖解析だ」）。図を1〜2枚入れる。
3. **つまずき／人間の部分** — うまくいかなかったこと、見落とし、対立、倫理的な問題。
   そら（遺伝カウンセラー）かハル（検査技師）に語らせると効く。
4. **いまにつながる線** — その出来事が現在の診療・検査・制度のどこに残っているか。
5. **ひかりの一言でしめる** — 学習者の言葉で意味づけをやり直す。

## 3. JSON スキーマ

```jsonc
{
  "part": 1,
  "afterDay": 5,                 // このDayの末尾に表示される（指示された値をそのまま）
  "kicker": "PART 1 修了エピソード",
  "title": "…",                  // 体言止めか問いかけ。20字前後
  "lede": "…",                   // 1〜2文。何の話で、なぜいま読むのか
  "minutes": 8,                  // 7〜10
  "era": "1951–1953 · ロンドン",  // 時代と場所。短く
  "blocks": [ /* SPEC.md と同じ talk / note / fig / list */ ],
  "connects": [                  // 学んだ概念との接続。3〜5個
    {"day": 4, "point": "…"}     // day は担当パート内の Day 番号のみ
  ],
  "takeaway": ["…"],             // 3〜5行。エピソードから持ち帰るもの
  "more": [                      // 3〜5件。さらに読むための手がかり
    {"what": "…", "note": "…"}   // 書名・論文・公開データベース・映画など。URLは書かない
  ],
  "caution": "…"                 // 任意。事実関係に留保がある場合のみ、その旨を1〜2文で
}
```

- `blocks` の `fig` は `flow`（年表）/ `pedigree`（家系図）/ `compare` / `table` が特に有効。
- 家系図を使う場合、**実在の家系を描くときは公表されている系譜の範囲にとどめ**、
  存命の個人の健康情報は描かない。
- `note` の `kind` は本編と同じ5種。`analogy` を1つ以上入れる。

## 4. 禁止事項

- 教科書本文の逐語訳・翻案。
- 存命の個人の診断名・検査結果の断定。
- 「感動的な物語」に整形するための事実の省略。**都合の悪い事実こそ書く**。
- URL の記載（オフライン単一HTMLのため）。`more` は書名・著者・年で示す。

## 5. 提出

`build/episodes/epN.json` に JSON のみを書き込み、
`python3 -c "import json;json.load(open('build/episodes/epN.json'))"` で構文を確認し、
最後に一行だけ「epN written: talk数/図数/接続数」と報告する。
