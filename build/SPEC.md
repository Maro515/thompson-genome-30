# 執筆仕様 — 「トンプソン遺伝医学・ゲノム医学 30日ゼミ」1日分のレッスン

あなたは『トンプソン&トンプソン遺伝医学・ゲノム医学 第3版』(原著第9版) を教材に、
**初学者が会話を追うだけで章の内容を完璧に理解できる**日本語レッスンを1日分書く。
成果物は `build/days/dayNN.json` という1個のJSONファイル。

## 0. 最初にやること

1. `build/days/day01.json` を読む。**これが品質・分量・文体の基準**。これ未満の密度は不可。
2. 割り当てられた章のOCRテキスト（パスは指示に含まれる）を読む。節構成・図表番号・BOX番号・
   固有名詞・数値・症例番号の**確認用**に使う。
3. `build/plan.json` の自分のDayエントリの `focus` を読む。**focus に挙がった項目は全て本文で扱う**。

## 1. 精度に関する絶対ルール

- OCRテキストは日本語OCRのため**文字化けが多い**。**そのまま引用してはならない**。
  構造（節タイトル・図表番号・登場する疾患名・遺伝子名・数値）を拾う手がかりとして使い、
  解説文はあなたの医学知識で正確に書き直す。
- **数値を創作しない。** 教科書本文またはOCRで確認できた数値、もしくは医学的に確立した標準値のみ書く。
  確認できない数値は「およそ」「〜程度」と書くか、書かない。統計・頻度・感度特異度をでっち上げるのは重大な誤り。
- 遺伝子記号は斜体の代わりに `*BRCA1*`（＝ハイライト表示）で書く。融合遺伝子は `*BCR::ABL1*` 形式。
- 人名を冠した疾患名は原著どおり `Down症候群` `Huntington病` `Prader-Willi症候群` のように書く（「ダウン症」等の略称は使わない）。
- 用語は本書の方針に従う: 基本語は **バリアント(variant)**。「変異(mutation)」は次世代に継承しうる
  変化そのもの/その過程に限定。顕性(優性)・潜性(劣性)は **「常染色体顕性遺伝(優性遺伝)」** のように
  初出で併記し、以降は顕性/潜性を使う。
- 他章に属する内容には `（第N章）` `（Day NN で扱う）` と明示して深入りしない。
- 断定できないことは断定しない。「議論がある」「まだ確立していない」と書いてよい。

## 3. インライン記法（本文・note・list・quiz・summary・cards すべてで使える）

- `**太字**` … 用語・結論の強調
- `*ハイライト*` … 遺伝子記号、英語原語、ここぞの一語（黄色マーカー表示）
- `` `コード` `` … 配列・表記法・コマンド的なもの（例: `46,XY,t(9;22)(q34;q11.2)`）
- 生のHTMLタグは書かない（`figure.kind:"svg"` の中だけ例外）。
- `caption` フィールドのみ `<b>…</b>` が使える。

## 4. JSON スキーマ

```jsonc
{
  "day": 7,                       // 指示された数値
  "chapter": "第5章 …",           // plan.json の値をそのまま
  "pages": "p.71–78",             // plan.json の値をそのまま
  "minutes": 28,                  // 20〜35
  "title": "…",                   // plan.json の title をそのまま使う
  "subtitle": "…",                // 1〜2文。その日の「勘所」を言う
  "goals": ["…"],                 // 4〜6個。「〜できる」で終える行動目標
  "keywords": [                   // 6〜12語。その日の必須用語
    {"term":"連鎖不平衡","en":"linkage disequilibrium, LD","def":"…"}   // def は2〜4文、**太字**可
  ],
  "scenes": [                     // 4〜6シーン
    {"heading":"…",               // 章の節に対応した見出し。体言止めか問いかけ
     "blocks":[ /* 下記のブロックを混ぜる */ ]}
  ],
  "summary": ["…"],               // 5〜8行。各行が独立して意味をなすこと
  "cases": [{"no":12,"point":"…"}],   // 0〜6件。その日の原理と直結する症例のみ
  "quiz": [                       // 5問（4肢択一を基本、3〜5肢可）
    {"q":"…","choices":["…","…","…","…"],"answer":2,"explain":"…"}   // answer は0始まり。explain は3〜6文で、なぜ他が誤りかも書く
  ],
  "cards": [{"q":"…","a":"…"}],   // 6〜9枚。q は口頭で答えられる問い、a は完結した答え
  "next": "…"                     // 次のDayの予告。何を開いて待つか（章・ページ）を書く
}
```

### ブロック型

```jsonc
{"t":"talk","who":"hikari","text":"…"}
{"t":"talk","who":"narr","text":"情景を一行で"}

{"t":"note","kind":"clinical|analogy|pitfall|exam|deep","title":"短い見出し","body":"2〜5文"}
//  clinical = 臨床メモ（診療でどう効くか）
//  analogy  = たとえで理解（比喩。1レッスンに必ず1つ以上）
//  pitfall  = つまずきポイント（よくある誤解）
//  exam     = ここは狙われる（試験・実務で問われる核心）
//  deep     = もう一歩深く（発展・例外）

{"t":"list","title":"…","ordered":false,"items":["…","…"]}

{"t":"fig","kind":"…","caption":"図の読み方を1〜3文で。<b>結論</b>を書く","data":{ … }}
```

### 図（kind ごとの data）— 1レッスンに **3〜6個**

```jsonc
// flow: 順序・経路。dir:"v" で縦積み（3段以上なら必ず "v"）
{"kind":"flow","data":{"dir":"v","steps":[{"label":"転写","sub":"RNAポリメラーゼIIが…"}]}}

// compare: 2〜3列の対比（最強の教材。積極的に使う）
{"kind":"compare","data":{"cols":[{"title":"常染色体顕性遺伝","items":["…","…"]},{"title":"常染色体潜性遺伝","items":["…"]}]}}

// table: 一覧。head と各 row の要素数を必ず一致させる
{"kind":"table","data":{"head":["","A","B"],"rows":[["頻度","…","…"]]}}

// stack: 階層・入れ子（DNA→ヌクレオソーム→染色体 など）。value は右端の数値ラベル
{"kind":"stack","data":{"layers":[{"label":"二重らせん","sub":"直径約2 nm","value":"2 nm"}]}}

// pedigree: 家系図。c=列(0始まり) r=世代(0始まり)。sex:"m"|"f"|"u"、aff=罹患、car=保因者、dec=死亡、prb=発端者
{"kind":"pedigree","data":{
  "nodes":[{"id":"I1","c":1,"r":0,"sex":"m","lab":"I-1"},{"id":"I2","c":2,"r":0,"sex":"f","aff":true,"lab":"I-2"},
           {"id":"II1","c":0,"r":1,"sex":"f","lab":"II-1"},{"id":"II2","c":2,"r":1,"sex":"m","aff":true,"prb":true,"lab":"II-2"}],
  "unions":[{"p":["I1","I2"],"kids":["II1","II2"]}]}}
//  ・夫婦は同じ r、間に1列空けず隣接させる。子は親の union の下の r に置く
//  ・unions の p / kids は必ず nodes に存在する id
//  ・列は詰めて配置する（c は 0,1,2… と連続させ、最大でも 9 まで）

// formula: 数式
{"kind":"formula","data":{"expr":"p² + 2pq + q² = 1","legend":[{"sym":"p","mean":"アレルAの頻度"}]}}

// seq: 塩基/アミノ酸配列にマーカー。i は0始まりの位置、len は長さ、tone:"accent"|"bad"|"ok"
{"kind":"seq","data":{"label":"βグロビン第6コドン","seq":"GTG CAC CTG ACT CCT GAG GAG","marks":[{"i":16,"len":3,"tone":"bad","note":"GAG→GTG"}]}}

// bars: 大小比較（単一色の量的比較。カテゴリ分けには使わない）。em:true で1本だけ強調
{"kind":"bars","data":{"unit":"%","max":100,"bars":[{"label":"一卵性双生児の一致率","value":45,"display":"約45","em":true}]}}

// svg: 上記で表せない図のみ。viewBox 必須、幅は 640 以内、色は var(--color-ink) / var(--color-accent) /
//      var(--color-line) / var(--color-paper) のみ使用。font-size は 10〜13
{"kind":"svg","data":{"svg":"<svg viewBox=\"0 0 640 200\" width=\"640\">…</svg>"}}
```

## 5. 構成のつくり方

1. **導入シーン**: 前日の内容を1〜2往復で思い出させ（`前のDayのタイトル`は指示に含まれる）、今日の問いを立てる。
2. **本体シーン(2〜4)**: 章の節構成に沿う。1シーン = 1つの大きな概念。必ず図か表を1つ入れる。
3. **臨床につなぐシーン**: その原理が診療のどこで効くか。そら／ハルの出番。症例提示に触れる。
4. 各シーンの終わりに note か らせんのまとめを置いてリズムをつくる。
5. 最後の talk は次への橋渡し（ただし予告本体は `next` フィールドに書く）。

## 6. 禁止事項

- 「復習」セクションを自作しない（アプリが前日までのカードから自動生成する）。
- 教科書本文の長い逐語訳・翻案を載せない。**自分の言葉で説明する**。
- 症例番号は指示に含まれる一覧に存在する番号のみ。関係が薄いものを無理に挙げない。
- `answer` の値と正解選択肢のずれ、`table` の列数不一致、`unions` の未定義id は**ビルドエラーになる**。書き終えたら自分で確認する。
- JSON は末尾カンマ禁止。文字列内の `"` はエスケープ。改行は入れない（必要なら文を分ける）。

## 7. 提出

`build/days/dayNN.json` に **JSONのみ**を書き込む（コードフェンス・前置き・コメント不可）。
書き込んだら `python3 -c "import json;json.load(open('build/days/dayNN.json'))"` で構文を検証し、
最後に一行だけ「dayNN written: シーン数/図数/クイズ数」と報告する。
